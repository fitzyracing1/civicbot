# Global free-API directory

The long-term goal is a verified list of all free public APIs and open feeds, for people, robots and AI
assistants. Batch 1 (2026-10-10) is published at https://fitzyracing1.github.io/civicbot/directory.html.
This is separate from the original 120-entry directory in `civicbot/data/free_apis.json`, which is unchanged and is
carried over here with the same ids.

## Layout

| Path | What |
|---|---|
| `candidates/<source>.json` | Everything collected, one file per source, with provenance. Written by `scripts/collect_apis.py`. |
| `candidates/dropped.json` | Duplicates, and candidates refused because their URL carried a credential-like parameter. Their URLs aren't stored. |
| `data/index.json` | Counts by continent, country, category, key type, kind, source and tier, plus the shard list and source licenses. |
| `data/<continent>.json` | Published entries, one shard per continent (`global.json` holds worldwide APIs). The site loads them on demand. |
| `failed.json` | Candidates that failed today, with HTTP status and reason, so they can be retried later. |
| `last_run.json`, `recheck_report.json` | Run summaries. |

## Entry fields

Old v0.4 fields are kept as they were. New fields are optional:

- **Identity and description:** `id`, `name`, `category`, `answers`, `kind`, `auth`.
  - `kind` is one of: api, gbfs, gtfs, gtfs-rt, portal, open311.
  - `auth` is one of: none, free-key, demo-key.
- **Location:** `country` (ISO 3166-1 alpha-2, plus EU), `country_name`, `city`, `continent`, `region`, `language`.
- **Links and format:** `docs`, `example`, `format`, `cors`.
  - `check` and `check_type`: what the verifier fetches and how it judges the reply.
- **Provenance:** `source` (a key into `index.json` → `sources`, with name, URL and license), `terms`, `limits`.
- **Verification:**
  - `tier`: `endpoint` means the example answered in the expected format. `docs` means only the documentation page loaded (from public-apis).
  - `verified` holds date, http, ms and mode. Also `verified_at` and `last_status`.
- **Paste into Grok:** `grok_prompt` is a one-line prompt for Grok with the verified URL. `grok_prompt_template` is
  optional and has `{place}` for skill-backed location APIs. Both are generated by `scripts/directory/prompts.py` at
  publish and site-build time.
  - `redirects` and `resolved`: redirect hops, recorded rather than followed silently.
  - `legacy`: true for the v0.4 entries, which are always kept and show their latest status.

## Running a batch

```
python scripts/collect_apis.py --cache /tmp/src          # gather candidates (no API is called)
python scripts/verify_apis.py --checkpoint /tmp/v.jsonl  # verify live, publish data/ and failed.json (~40 min)
python scripts/verify_apis.py --sources curated          # re-verify one source, keep the others
python scripts/build_site.py _site                       # site + grok-global.txt + per-region text files
```

To add APIs, add rows to `scripts/directory/curated.py` (or write a new parser in `sources.py`) and rerun.

Verification rules:
- an identifying User-Agent, one GET per candidate, at least 1.2 s between calls to the same host
- a 20 s timeout and one retry on network errors, 429 or 5xx
- up to 3 redirects, each recorded
- no keys are ever used: free-key APIs are listed as "reachable (key required)" when they answer 401/403

The weekly workflow `.github/workflows/directory-recheck.yml` re-checks published entries. It opens or updates one
issue listing the dead ones and never deletes anything.
